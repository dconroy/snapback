# QuickCap Hardware Bring-Up

Date: 2026-10-05

## Network Reachability

Tested hostnames:

- `quickcap.local`
- `quikcap.local`

Initial result: neither hostname resolved from the development machine.

Follow-up result: the Pi is reachable as `quikcap.local`, and TCP port 22 is open. The alternate spelling `quickcap.local` does not resolve.

Commands attempted:

```sh
dscacheutil -q host -a name quickcap.local
dscacheutil -q host -a name quikcap.local
ping -c 1 -t 3 quickcap.local
ping -c 1 -t 3 quikcap.local
nc -G 3 -z quickcap.local 22
nc -G 3 -z quikcap.local 22
ssh -o BatchMode=yes -o ConnectTimeout=5 -o StrictHostKeyChecking=accept-new quickcap.local uname -a
ssh -o BatchMode=yes -o ConnectTimeout=5 -o StrictHostKeyChecking=accept-new quikcap.local uname -a
nc -G 3 -z -v <pi-lan-address> 22
ssh -o BatchMode=yes -o ConnectTimeout=5 -o StrictHostKeyChecking=accept-new pi@<pi-lan-address> uname -a
ssh -o BatchMode=yes -o ConnectTimeout=5 -o StrictHostKeyChecking=accept-new quickcap@<pi-lan-address> uname -a
ssh-keyscan -T 3 <pi-lan-address>
ssh pi@<pi-lan-address>
hostname
hostnamectl
uname -a
cat /etc/os-release
cat /etc/rpi-issue
cat /proc/device-tree/model
dpkg --print-architecture
lsblk -o NAME,MODEL,SIZE,TYPE,FSTYPE,MOUNTPOINTS
df -h /

git --version
ffmpeg -version

ls -l /dev/video*

ffmpeg -hide_banner -f v4l2 -list_formats all -i /dev/video0
lsusb
gpioinfo
```

Observed results:

- `ping` could not resolve either hostname.
- `nc` could not check TCP port 22 because name lookup failed.
- `ssh` could not reach authentication because name lookup failed.
- Bonjour SSH service browsing was attempted with `dns-sd -B _ssh._tcp local.`, but the local DNS-SD service reported `DNSServiceBrowse failed -65563 (Service Not Running)`.
- Direct TCP port 22 probing succeeded.
- Passwordless SSH was not available for the tested usernames `pi` or `quickcap`.
- Interactive SSH with the configured `pi` user succeeded.
- The SSH service banner reported OpenSSH on Debian.
- After login, `quikcap.local` resolved and SSH succeeded by hostname.

No credentials were stored. The Pi LAN address is intentionally not stored in this repository.

## Capture Hardware

Detected USB capture device:

- Elgato Cam Link 4K
- USB ID: `0fd9:00a1`
- V4L2 capture device: `/dev/video0`
- V4L2 metadata device: `/dev/video1`
- Driver: `uvcvideo`

Supported capture formats reported by V4L2 and ffmpeg:

- `YUYV` up to 1920x1080 at 60 fps
- `NV12` up to 3840x2160 at 30 fps
- `YU12` / `yuv420p` up to 3840x2160 at 30 fps
- `MJPG` up to 3840x2160 at 60 fps

A one-frame ffmpeg capture test from `/dev/video0` to `/tmp/quickcap-test.jpg` succeeded at 1920x1080 using MJPEG input. The temporary file was removed after the test.

Expected first capture device signal on the Pi:

```sh
lsusb
```

## Dependencies To Verify Later

The core bring-up dependencies are already present. Re-run these checks after OS upgrades or reimaging:

```sh
python3 --version
git --version
ffmpeg -version
v4l2-ctl --version
lsusb
gpioinfo
```

If basic capture tools are missing after a future reimage, the proposed Raspberry Pi OS install command is:

```sh
sudo apt update
sudo apt install -y git python3 python3-venv python3-pip ffmpeg v4l-utils usbutils gpiod
```

Do not run this until SSH access is confirmed and the package list has been reviewed.
