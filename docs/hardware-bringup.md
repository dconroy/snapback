# Snapback Hardware Bring-Up

Date: 2026-10-05

## Network Reachability

The Pi is reached by its mDNS name, `snapback.local`, on the home network.

What bring-up found:

- At first the hostname did not resolve from the development machine, so `ping`, `nc`, and `ssh` by name all failed. Bonjour browsing (`dns-sd -B _ssh._tcp local.`) reported `DNSServiceBrowse failed -65563 (Service Not Running)`.
- Direct TCP probing of port 22 on the Pi's LAN address succeeded. The SSH banner reported OpenSSH on Debian.
- Passwordless SSH was not set up; interactive SSH as the `pi` user worked.
- After logging in once, the `.local` name resolved and SSH by hostname worked.

Commands used:

```sh
dscacheutil -q host -a name snapback.local
ping -c 1 -t 3 snapback.local
nc -G 3 -z snapback.local 22
nc -G 3 -z -v <pi-lan-address> 22
ssh-keyscan -T 3 <pi-lan-address>
ssh pi@snapback.local
hostname
hostnamectl
uname -a
cat /etc/os-release
cat /etc/rpi-issue
cat /proc/device-tree/model
dpkg --print-architecture
lsblk -o NAME,MODEL,SIZE,TYPE,FSTYPE,MOUNTPOINTS
df -h /
free -h

python3 --version

```

No credentials were stored. The Pi LAN address is intentionally not stored in this repository.

## Capture Hardware

Detected USB capture device:

- Elgato Cam Link 4K
- USB ID: `0fd9:00a1`
- V4L2 capture device: `/dev/video0`
- V4L2 metadata device: `/dev/video1`
- Driver: `uvcvideo`

Supported capture formats reported by V4L2 and ffmpeg:

- `YUYV` up to 1920x1080 at 60 fps
- `NV12` up to 3840x2160 at 30 fps
- `YU12` / `yuv420p` up to 3840x2160 at 30 fps
- `MJPG` up to 3840x2160 at 60 fps

A one-frame ffmpeg capture test from `/dev/video0` to `/tmp/snapback-test.jpg` succeeded at 1920x1080 using MJPEG input. The temporary file was removed after the test.

Expected first capture device signal on the Pi:

```sh
ls -l /dev/video*
v4l2-ctl --list-devices
lsusb
```

## Dependencies To Verify Later

The core bring-up dependencies are already present. Re-run these checks after OS upgrades or reimaging:

```sh
python3 --version
git --version
ffmpeg -version
v4l2-ctl --version
lsusb
gpioinfo
```

If basic capture tools are missing after a future reimage, the proposed Raspberry Pi OS install command is:

```sh
sudo apt update
sudo apt install -y git python3 python3-venv python3-pip ffmpeg v4l-utils usbutils gpiod
```

Do not run this until SSH access is confirmed and the package list has been reviewed.
